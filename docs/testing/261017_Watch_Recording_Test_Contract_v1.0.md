## Package A — tests before production

Use the production codec, store and recovery reader against isolated temporary directories. Hardware is absent from this package. Test fixtures contain synthetic numbers, not player data.

| Contract | Required evidence |
|---|---|
| Raw representation | Round trip both declared streams, timestamp precision, units, coordinate/clock identity, setup/build/capability metadata and exact sample counts. Equivalent inputs produce identical bytes. |
| Validation | Reject unsupported versions/streams, wrong component counts, NaN/infinity, invalid clock anchors, nonmonotonic samples, contradictory bounds/counts, duplicate/conflicting session and sequence IDs. |
| Bounded work | Adopted encoded chunk limit 1 MiB: test at the limit and just beyond it. Decide and record further codec and byte/sample/count limits before production edits; test each boundary. Reject oversized input before allocating its claimed size. Recovery must bound file count, bytes and memory. |
| Write correctness | Create directories exclusively; never overwrite another recording. Write/check/synchronize/publish completed chunks before final index. Finalization verifies identity, sequence, checksums and counts from stored bytes. No successful saved result after write/sync/rename/readback/finalization failure. |
| Fault injection | Through narrow file-operation seams, force short writes, I/O errors, disk-full, failed publication and failed final manifest. Assert truthful return/status and preservation of previously completed chunks. Defaults must remain real file operations. |
| Interrupted recovery | Inspect cuts at creation, temporary chunk, published chunk without manifest update, and incomplete finalization. Retain recoverable evidence and classify interrupted/partial; never claim normal completion. |
| Abrupt process death | Terminate a child-process storage writer at defined boundaries and reopen its files. Distinguish this from ordinary injected errors. No hardware/power-loss guarantee follows. |
| Finalization | Repeated finalization is safe. Append-after-finalization, cross-session overwrite and reopening under another boot clock are rejected. |
| Integrity/security | Detect modified/truncated/reordered chunks, missing files, checksum mismatches, unsupported metadata, unexpected file types/symlinks and path traversal. Stay within the owned root; do not follow or overwrite external paths. Corruption stays visible. |
| Non-destructive inspection | Recovery does not rewrite source timestamps, delete unknown/corrupt files or silently manufacture completion. Repeated inspection gives the same classification. |
| Regression | Existing 29 core tests stay applicable and pass with new tests. Build both app schemes in Release on OS 27; no change to current UI/permissions/signing. |

Allowed test additions: `RecordingModelsTests.swift`, `RecordingChunkCodecTests.swift`, `RecordingStoreTests.swift`, minimal synthetic fixtures and a test-only abrupt-process-death helper under the existing PadelCore test target. No new dependency by default. Scope extensions require a revised contract first.

## Concrete engineering constants — frozen before package A source edits

These are defensive format/inspection limits, not approved capture rates, duration or battery claims.

- Chunk schema 1: little-endian binary, 72-byte header and 32-byte SHA-256 trailer; maximum encoded input/output 1,048,576 bytes (1 MiB). The header records recording/clock UUIDs, stream, independent zero-based sequence, count and exact first/last source timestamps. Each sample is timestamp plus declared IEEE-754 Float64 components. Acceleration has x/y/z in g; device motion has rotation x/y/z (rad/s), gravity x/y/z (g), user acceleration x/y/z (g), attitude quaternion x/y/z/w (unitless). Coordinate convention is the unmodified Core Motion device frame. All values are finite; source seconds are nonnegative and strictly increasing per stream, including chunk boundaries. No sorting, interpolation or timestamp substitution.
- Maximum samples per chunk: 32,764 accelerometer / 9,361 device-motion (the greatest whole-sample payload fitting the byte cap). Exact 1 MiB malformed input is inspected/rejected as malformed; 1 MiB + 1 is rejected for size before parsing. Tests exercise largest legal payload and one extra sample for each stream.
- Metadata maximum 16,384 encoded bytes; each free-text field 1–128 UTF-8 bytes with no control characters. Canonical JSON uses sorted keys; strict decoding must reproduce the original bytes, rejecting unknown/duplicate fields and alternate unsupported encodings. Metadata records caller-supplied build/protocol/device/OS/setup/capability/requested-rate values; unknown physical facts remain explicitly absent. Clock UUID and finite nonnegative monotonic anchor are separate from finite wall seconds. Recording IDs and clock IDs are supplied explicitly.
- At most 256 chunks across both streams, each sequence starting at zero and advancing independently. Manifest maximum 262,144 bytes. Finalization records caller-supplied stop-request source seconds and reason, plus verified retained per-stream ranges/counts; it does not assert uninterrupted capture or observed data through stop. Stop cannot precede any retained sample. Repeating identical successful finalization is idempotent; changed requests and further appends fail. A reopened store is inspection-only; capture never resumes across reopen/clock change.
- Recovery inspects at most 272 directory entries and reads at most 268,976,128 bytes (256 MiB plus 528 KiB metadata/manifest allowance); smaller inspection budgets may be supplied for tests/callers, never larger. Each read is capped before allocation, and only one bounded chunk is decoded at once. Results retain descriptors/issues, not all raw sample arrays. Exceeding any scan/read budget gives an explicit limited, never finalized, result. Unknown entries, symlinks, partial temporary files, missing/corrupt/inconsistent indexed chunks and valid orphan chunks remain in place and are reported. Valid orphans are recovered in the report only; no manifest is rewritten and missing finalization never becomes completion.
- Synchronous, single trusted caller; no concurrent or hostile-writer guarantee. Open absolute pre-existing root directories without following symlinks in any component; reject traversal. Create UUID recording directories exclusively. Private directory/file modes 0700/0600. Real writes loop over short writes, synchronize the temporary file, exclusively link-publish immutable chunks, synchronize the directory, then atomically replace/synchronize the manifest. No overwrite of raw chunks. Finalization rereads stored bytes and validates identity, sequence, checksums, counts and coverage before committing its manifest. API success is not a universal hardware power-loss guarantee.
- Production-path tests cover both streams/precision/metadata; all count/byte/text/scan boundaries; clock/session/sequence conflicts; NaN/infinity/timestamp order; bit corruption/truncation/unknown schema/extra fields; modified/missing/orphan files; traversal/symlinks; full and short real writes; injected ENOSPC/EACCES/EIO at write/sync/publish/manifest/finalize boundaries; readback failure; repeated finalize/append rejection; non-destructive recovery and abrupt child-process exit after temporary write, published chunk and final-manifest publication. Child process tests are macOS-only and prove process interruption, not Watch/power-loss behavior.

## Later contracts — required before live-capture production edits

- **Sensor/timing:** unsupported hardware, denied motion access, absent/empty/malformed batches, independent stream errors, actual timestamp vs callback timing, gaps/duplicates, clock resets and stop-tail uncertainty. Sensor mocks prove control paths only.
- **Lifecycle/permissions:** no start before confirmation/authorization; initial failure/timeout; exactly one active session; pause/resume; double stop; cancellation at each asynchronous boundary; late callbacks; bounded queues; storage failure; unexpected workout termination; restart/reboot recovery; all resources released.
- **UI:** accessible native controls, visible recording/paused/stopping/interrupted/error states, disabled unsafe actions and honest saved/coverage wording in the existing premium theme. Simulators cannot prove real permission/sensor behavior; do not add hidden fake recording to production.
- **Physical Watch/iPhone:** exact installed build, current OS, authorization denied/granted, high-rate support and observed rates, wrist lowered/background, phone disconnected, other-workout conflict, stop-tail coverage, force interruption/relaunch, low storage, battery/thermal impact and repeat sessions. Give the owner one physical action at a time. No physical install occurs during planning.
- **Retrieval:** a separate package must prove end-to-end identity/sample counts/checksums before collection is accepted as a usable court experiment.
