## 4. Owner practice, Health and recovery

Reuse the legitimate owner workout needed by batched motion, with one explicit owner practice spanning bounded sets/rest. States are ready, starting/baseline, active set, between-set recovery, ready/paused practice, ending, ended/interrupted. Motion runs only inside set capture. Pause set retains existing raw pause semantics; Pause practice pauses the workout and marks recovery partial/unavailable. End practice ends all source/query/workout resources; raw set Stop alone may enter recovery. No silent indefinite workout or automatic capture restart after relaunch.

Operational safety defaults for this candidate: maximum practice elapsed time 30 minutes; maximum 20 sets per practice; automatic recovery observation ends at +130 seconds and then pauses the workout pending explicit user continuation; a new set may start earlier after fresh confirmation, making unreached recovery windows missing. These are resource bounds, not medical or performance thresholds. Timer/error/limit closure must work offline and survive state transitions; interruption/relaunch retires authority and requires new preparation. Startup/shutdown state requests use a five-second bounded acknowledgement window consistent with the existing driver; timeout fails visibly, never reports clean shutdown.

HR uses only authorized standard heart-rate samples for the current owner practice interval, retaining sample UUID, start/end dates, source/device provenance and arrival time. No unrelated/history query or inferred read-denial state. Request only required workout sharing authorization and optional heart-rate read authorization; do not request HR write, routes, energy, VO₂, blood oxygen or other types. Successful authorization requests do not prove readable HR. Empty, sparse, denied-looking or delayed results appear as **No accessible heart-rate data** or coverage-specific missing values. No raw PPG, high-frequency-HR or OS27-only feature promise is required.

The query combines a strict-start current-practice date predicate, fixed upper bound no later than the30-minute practice limit, and `HKQuery.predicateForObjects(from: [HKDevice.local()])`. Reject user-entered samples and postvalidate the whole source interval against the actual admitted practice/observation bounds and matching local-Watch device descriptor. Missing/mismatched device provenance is excluded with a count/reason; there is no wider source/history fallback. Preserve source revision bundle/version/OS/product type and minimal manufacturer/model/hardware/software plus app installation epoch; exact HealthKit device equality stays runtime-only. Do not persist/export user-custom device/source display names, Apple-account identifiers or system device identifiers. `HKSource.default()` is not a proxy for system-generated HR. This public SDK filter is a proposed capture restriction, not proof that physical Ultra2 samples will match; no matching data remains an honest missing-data result.

Preferred minimal SDK-supported path is the existing `HKWorkoutSession` plus a bounded current-practice heart-rate anchored query; a builder is unnecessary if that query provides actual timestamped samples. If SDK/physical evidence requires `HKLiveWorkoutBuilder`, implement it only within H after review, restrict its data collection and discard at End. Never synthesize point samples from builder aggregates. Neither path calls `finishWorkout` or saves an app workout summary. An active Health workout can cause system-generated samples and Activity effects even without a builder or saved summary; discard/app deletion does not promise to erase them. Explicitly document/verify actual requested types, query predicate and End semantics.

Recovery calculation version 1: median of ≥2 valid samples in the30 seconds preceding set Start; median of ≥2 in the final10 seconds before set Stop; median of ≥2 in each +60/+120 second ±10 second window. A standard recovery window is eligible only when its entire interval completes inside one uninterrupted observed recovery segment: +60 requires observation through+70, +120 through+130. Before completion it is pending; next set, Pause practice, End or interruption before the upper boundary makes that standard value missing. Do not emit a clipped window as a completed target value. Samples must have their whole source interval inside one eligible observation segment; then use the end timestamp for deterministic window membership. Preserve actual sample dates/counts/spans. Use signed `end-reference minus later-window` BPM, including negative values. Missing baseline or end reference makes dependent results missing; first-set baseline may legitimately be missing and never forces unrelated-history access or extra setup. Baseline comparison is descriptive, with no “normal”, readiness, fitness score or diagnosis. Do not interpolate missing windows or assume monotonic decline.

Wall-clock HR intervals retain their original time domain; motion retains boot-monotonic timestamps. Persist practice start wall/monotonic anchors, clock domain and measured mapping uncertainty. A detected wall/monotonic discrepancy >2 seconds creates a discontinuity; affected set alignment/recovery is unavailable rather than silently shifted. Timezone display changes do not alter Unix times. Preserve samples crossing a window boundary but include in a median only samples whose end timestamp lies inside that window, using one documented deterministic rule. Distinct UUIDs are separate samples; exact repeats are idempotent; same UUID/conflicting content is quarantined and marks coverage invalid.

## 5. Telemetry, transport, export and deletion contract

Drain for at most five seconds at End, then finalize explicit incomplete coverage; samples arriving later cannot mutate finalized content. No callback-time reassignment to a later practice. Reopening partial data retains interruption; it never turns an unfinished manifest into complete evidence.

The research-envelope unit is one **ended/interrupted, finalized whole practice**, containing its frozen inventory of at most20 sets. Each set contributes one existing raw archive (which already contains its timeline and label-history snapshot) and one immutable owner context; practice manifest and HR telemetry/absence descriptor are shared. Maximum64 components and256 MiB cover the40 set components plus bounded practice companions. Existing tighter raw limits remain binding. Each component records required/optional status, schema, identity, bytes and SHA-256; no duplicate external timeline/label component is needed. A raw receipt never proves companion transfer. Context-free legacy exports remain **unassigned legacy raw only**, never complete owner evidence. Oversized practice export fails explicitly without truncating its inventory; no complete receipt follows.

Use the existing sole `RecordingConnectivity` owner and completion-counted async admission; no second `WCSession` delegate. Owner wire2 is explicit: wraps the frozen P1 draft/identity plus mandatory owner/consent/practice binding and typed status/prepare/retire/deletion/receipt operations; exact canonical encoding with ≤32 KiB message limit. Unsupported or older peers cannot strip bindings or fall back to wire1. Application context is draft-only, never acceptance. Persist bookkeeping before acknowledging and revalidate after every suspension. End/retired identity stays retired across reconnect/replay. Existing raw queue/receipt transfers continue independently and keep their semantics.

Whole-envelope transfer is asynchronous, idempotent and conflict-detecting. Import stages into a private bounded namespace, verifies all included components before publishing the complete receipt, and quarantines conflicts without overwriting originals. Test receipt/transfer/import/export/Delete races against the actual transaction/lease paths. Source copies remain after transport completion and after receipt; only explicit deletion removes them. If HR is excluded, the manifest says excluded rather than complete-HR evidence. Sharing does not authorize unrelated upload and external exported copies cannot be recalled by app deletion.

Delete local recording removes raw, labels/timeline companions, set context, set-specific derivatives/caches/export temporaries, and its membership in the practice's retained set inventory. No misleading success while deleted-set HR remains accessible. Delete practice removes every covered set and companion. The simplest safe first UI may offer **Delete entire practice** for new owner bundles and retain historical Delete local recording for legacy raw data; make that scope explicit before confirmation.

Durable deletion tombstone precedes removal. Close active capture/query/export/import admission and acquire existing leases; never delete an active set while its writer runs. Crash recovery completes a pending deletion, rejects reimport/late receipt for the deleted identity and reports partial/failed cleanup honestly. All app-owned staged/temp/cache copies are included. Tombstones contain only IDs/digests/status needed to prevent resurrection, no HR/raw/labels. Paired Delete sends an idempotent scoped command and leaves **Watch cleanup pending** until acknowledged after actual covered cleanup; disconnected Watch data is never reported gone. Local completion and paired completion are distinct observable states. External exports and independent system Health data are explicitly outside this operation. This paired cleanup is included for the owner candidate; guest withdrawal is still deferred.
