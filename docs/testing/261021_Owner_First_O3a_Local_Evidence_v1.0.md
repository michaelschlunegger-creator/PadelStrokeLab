## Implemented behavior and coverage

`OwnerAuthorityMutation` is a compact typed command with a4KiB canonical limit. It binds owner, exact phone/Watch installation epochs, immutable operation ID, policy, before revision/consent generation/withdrawal barrier, before digest and expected after digest. Only initial revision1 enrollment includes a full authority value. Other commands reconstruct through frozen O1 functions and compare the exact resulting digest; no arbitrary status authority imports or guessed revision increments exist. Grant/re-consent commands cannot use restriction rebasing. The narrowing rebase helper preserves the decision ID/time and requires the same owner/peers, consent generation and withdrawal barrier; its name and contract require the future journal to verify the intervening revision-only chain first.

`OwnerAuthorityTransition` carries one compact command. Its positive sequence equals the resulting authority revision, because every supported transition advances once from initial enrollment. Its separate canonical checksummed envelope is at most4KiB. An ACK binds exact owner/peers, sequence, transition digest and resulting authority digest. Replay names an exact acknowledged cursor and returns at most one successor; the successor must match the peer tuple, next sequence and before digest. A nil cursor permits only initial enrollment. Pure ACK/replay values do not prove that a device persisted anything.

Preparations bind exact active owner authority, practice ID and frozen P1 draft identity, and permit only manual forehand/backhand with either playing arm. A preparation request must contain its exact correlated identity. Acceptance requires the exact owner/peers, both generations and current/next accepted identity. Retirement requires advanced authority, the same runtime generation, a rotated preparation generation, cleared accepted identities and the exact End/Cancel reason. An applied-transition reply matches the original request ID, both generations and full mutation. Typed failures match the request ID and digest of the complete canonical request, including its peer/generation/content. Status is observation only, including explicit unavailable/unknown fields; there is no Start message or authority-store operation.

`OwnerPreparationCodec` permits only canonical `PSLOwnerSetup2` values within32KiB. Decode/re-encode equality rejects unknown/duplicate/irrelevant fields, noncanonical alternatives, unsupported versions/kinds and oversized input. Checked nested decoders validate preparation identities, observations, transitions, acknowledgements and replay cursors. Tests cover a literal independent discovery wire, both strokes/arms, wrong/withdrawn owner bindings, exact and stale correlations, missing/foreign/unadvanced retirement observations, command policy/peer/digest/field tampering with recomputed checksums, grant/re-consent rebase refusal, contiguous replay and the maximum128-decision authority history. The latter still fits status wire and compact HR-disable/withdrawal commands without repeating full identities.

## O3b/O3c obligations and handoff

O3b must durably append before O2 application, locate actual store authority at an exact chain node on recovery, verify the resulting bytes before acknowledging, retain/prune only an exact contiguous acknowledged prefix and reconcile the O2 guard-present/authority-before retirement edge with exactly one verified advancement.
