## Implemented contract and director clarifications

The synchronous, non-Sendable channel exclusively owns both its journal and frozen O2 store. Watch alone sequences explicit enrollment/consent/revision/practice-retirement transitions. Phone saves one intent and mirrors exact transitions; no status snapshot imports authority. Application code receives no mutable O2 handle. Every later Watch O2 apply/advance/practice-retire must pass this sequencer, including O5/O7/O9. Context publication shares this serial ownership, and checked snapshots expose the current O2 `storeInstanceID` so O5 can compare an actual publication against the current owner after reopen.

Watch appends and synchronizes before O2 application, verifies actual resulting authority before returning, and retains transitions until an exact durable phone ACK. Phone records each received transition before O2 application and any intent/checkpoint change before returning ACK. Reopen validates the committed chain, synchronizes the loaded journal file and directory, locates actual O2 at an exact anchor/intermediate/tip node, and applies only committed successors. A guard-present/authority-before interrupted practice retirement performs exactly its one committed advancement; a fresh repeated End against an existing guard is rejected.

One checksummed canonical journal is bounded to1MiB/256 transitions, compact transitions to4KiB, and its acknowledged O1 anchor to O1's16KiB limit. Ordinary work and prospective admission preserve separate count, byte and revision capacity for End, actual HR true-to-false and full withdrawal. Each reserved category is consumed at most once until acknowledged; generic advance, redundant HR-false and repeated End cannot reuse these reserves. All three valid restriction orders exercise actual253/256 production boundaries. Independent near-limit O1 authority tests verify admission closes before only the three necessary revisions remain.

The director ratified these bounded clarifications during independent review, without adding a second queue, another domain or another production file:

- A refused conflicting privacy restriction durably raises a separate **none/HR/all local fence**, then returns `intentOutstanding`/not queued. Snapshot distinguishes this fence from the one saved/dispatched command. HR and full fences both block new admission; HR fences block HR analysis/export access and full fences block all such access. The latch never claims the refused second command was remotely applied.
- End is admission control, not a consent privacy fence. A refused End remains honestly not queued; the original pending intent still blocks admission. An exact End or unrelated grant ACK cannot clear an HR/full fence. An exact matching restrictive intent/ACK can clear only the scope it satisfies.
- `resolveSatisfiedRestriction(expected:)` is an explicit phone-only human-resolution operation. It requires no pending intent and the exact current ACK, including owner/epochs, sequence, authority digest and transition digest. It clears all only when collection is already denied, or HR only when HR is already denied. It grants no authority. An obsolete pending intent must first use the existing verified resolution API; the fence persists until the separate explicit operation. Status, timeout, End and grant/reconsent acknowledgements cannot clear it.
- While authority is nil and an exact retained **dispatched enrollment** exists, a conflicting withdrawal/HR-disable may validate solely against that enrollment's exact proposed O1 result to raise the local fence and return not queued. Unsent enrollment conflicts, grants, unrelated owners/epochs/base states are not admitted through this exception. The original enrollment and dispatched bit remain unchanged; a later enrollment ACK/reopen preserves the fence.
- After actual phone mirror/O2 verification, a non-stale unfulfilled restrictive intent may atomically checkpoint a verified revision-only chain into the exact current anchor/ACK and one effective rebased command. Its decision ID/time/kind/owner/epochs/policy, dispatched bit and local fence remain unchanged. One immutable original-command digest permits exact original retries without restoring the old base; no second command payload is retained. This avoids stranding a matching withdrawal after256 acknowledged intermediate transitions. Grants/reconsent/stale intents never use this compaction; their explicit-resolution proof remains retained. Checkpoint persistence precedes ACK.

Descriptor-relative no-follow regular-file checks, exclusive lock ownership and namespace identity checks protect live operations. Publication rechecks the held temporary's inode/contents and the expected committed journal before replacement. Any ambiguous publication/application poisons the channel. **Any remaining `journal.pending` is preserved and blocks reopening**; it is never promoted, discarded or treated as a committed authority action. Ordinary committed-journal recovery is automatic. No personal recovery/deletion or raw payload cleanup is implemented here. O5 independently owns immediate resource shutdown even if durability, capacity or revision checks fail.
