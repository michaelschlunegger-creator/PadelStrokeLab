# Padel Master — first physical recording runbook v1.0

20 October 2026, Asia/Dubai. Expected candidate: version 1.0/build 6. This is a test procedure, not evidence of completed installation or recording. The last verified physical installation is the prior build 4 logger.

## Before installation

Finish the branding package's local builds, tests, simulator visual inspection and exact source record. Obtain the repository-required publication approval, current CI and independent committed-source review before replacing the physical apps. Obtain the owner's approval for the concrete replacement build; verify signing and device reachability at that time. Install, query version/build and launch iPhone and Watch separately. An embedded Watch app or successful iPhone launch does not prove Watch installation.

The coordinator gives one observable action at a time and records the result before advancing. Use the owner's iPhone 15 Pro and Watch Ultra 2; verify their actual current OS versions. Keep raw device identifiers, recordings and logs private. Do not submit the App Store record or incur costs as part of this test.

## Preparation — every new set

1. End other workout sessions. Put the Watch on the arm holding the racket. If moving it locks the Watch, unlock it and return to Padel Master. The app cannot sense which arm actually wears it.
2. Tap **Let’s Play** on Watch. At **Your racket hand**, select/acknowledge the current racket hand and usual handedness, then confirm. Stored suggestions do not authorize a new set.
3. At **Watch on racket arm**, confirm its actual physical placement. At **Watch orientation**, compare the displayed watchOS wrist/crown configuration with how it is worn. Correct mismatches in Watch Settings, return, refresh and freshly confirm.
4. At **A comfortable fit**, secure the strap comfortably and confirm. At **Your shot type**, choose and confirm **Forehand groundstroke** for the first test.
5. At **Ready for this set?**, review the summary, freshly confirm placement/fit and tap **Start recording**. Record any workout/motion permission prompts and outcomes. Expected on supported physical hardware: Recording state and increasing accepted accelerometer/device-motion counters. A capability, permission, storage or start error is a failure to record and investigate, not a reason for repeated blind retries.

Back and Cancel remain available. Leaving the foreground before capture requires renewed physical confirmation. Each subsequent new set repeats preparation; Pause/Resume stays within an existing set. Existing capture limit is 120 active seconds, excluding pauses.

## One dry run before ball contacts

Make one controlled air swing without touching the screen. Tap **Stop and save** and wait for Watch-local saved/verified status. Accepted live samples and durable saved chunks have different meanings; log both observed values and any interruption.

Retrieve the set on iPhone, verify the receipt and matching intended-shot/setup metadata, inspect coverage, add an **Air swing** self-reference label and export. Read back the export and reconcile session identity and retained sample counts. Keep the Watch original until the phone and export are verified. Air swing is not a ball-contact quality label.

Only after this end-to-end dry run succeeds, record one controlled forehand ball contact per short set initially and add an honest clean-contact/mishit/uncertain self-reference label. Unmatched time intervals remain uncertain. Expand to multiple attempts or other shot types only when matching remains reliable. No automatic clean-hit score or validated quality detector is provided by this recording prototype.

## Evidence and subsequent checks

Record exact committed source/build, both devices/OS, playing arm, wrist/crown, permission outcomes, requested/observed capture mode, timestamps/gaps, stop/save status, phone receipt, export read-back and failures. Then follow the existing [physical logger runbook](261019_Physical_Shot_Logger_Runbook_v1.0.md) for interruption/recovery, absent-phone/later delivery, transfer retry, label revision, export and local-delete checks, using this mandatory wizard instead of its older preparation entry.

Simulator automation cannot establish real sensor fidelity, background survival, delivery, battery or court ergonomics. One successful dry run proves one observed recording workflow; it does not establish general reliability or contact-quality prediction.
