## Independent review correction — import/delete/ack transaction (defined before source)

Review found that phone deletion could remove already-inspected raw files while an import recreated notes and published a receipt. Add a common per-recording transaction held across archive validation/install/receipt, phone local deletion, and acknowledgment decisions. Persist a durable deletion tombstone in a private ledger outside the deleted UUID folders before removing data. Automatic duplicate or delayed transfers must fail with `Deleted on this iPhone`; they cannot recreate intentionally deleted raw/notes or emit Verified. An acknowledgment legitimately queued before a later owner deletion remains historical transfer evidence, not a promise that the phone retains a copy forever.

Deterministic production-path regression: stop duplicate import at the pre-receipt barrier while it owns the transaction, concurrently request phone deletion, verify deletion is blocked until import completes, then verify deletion removes the local copy, durable tombstone survives reopen, acknowledgment decision rejects and duplicate retry cannot resurrect data. A second test deletes first and verifies import cannot install raw/notes. Retain label-preserving duplicate tests and assert exports/Watch source remain untouched. Use real POSIX locks/files; only barriers and the acknowledgment send action are test seams. This bounded correction touches shared archive/connectivity, one new transaction helper, phone deletion integration and associated tests, within eight production files/two Level3 domains.

Additional independent-review regressions, before source: a live/paused capture holds an exclusive nonblocking capture lease outside its raw UUID folder; export takes the same lease and must fail while capture is active, then succeed after explicit release/seal. Private incoming copies are stored under their recording UUID, removed after durable verified import/ack preparation, and removed with failed staging copies by explicit phone-local deletion. The deletion tombstone guards copying as well as import; delayed transfer cannot recreate an inbox copy. Exports remain independent and are not deleted. Tests inspect actual private directories and use lock barriers, not mocked file deletion.

## Watch background completion contract — defined before source

The singleton Watch connectivity service exposes bounded background drain requests. A successful completion requires an activated real WCSession, no `hasContentPending`, and zero admitted owner I/O jobs. Poll on a serial-owner timer without blocking that owner; each request completes once, fails on explicit cancellation/expiration or a 30-second monotonic deadline, and never deletes queued/persisted data. Limit8 simultaneous drain requests. Tests inject only WC readiness state and timeout; actual production admission/owner queue and completion logic remain unchanged. Verify content-pending gate, real blocked owner-job drain, cancellation exactly once, timeout and persistence retention.
